So the ratings stay consistent from run to run, don't call something a validation gap unless it's actually one of these: a required field got accepted empty, a unique field took a duplicate value, a field with a defined format or range or length or allowed list took something outside that definition (say exactly which rule and value broke it), a record got saved referencing something that doesn't exist, a value got through that breaks a rule you can point to in the code, schema, ORM model, migration, or API spec, or the same underlying failure gives a different error message depending on which form triggered it. "Seems off" or "looks unusual" isn't a real reason on its own, always tie it back to the specific rule and value.

Severity works the same way. Call it Critical if the accepted data could corrupt a record, break a relationship between entities, or open up a security hole, like unescaped input getting reflected back. Call it High if invalid data got saved despite a schema or validation rule, but it's contained to that one record and doesn't touch other data, auth, or security. Call it Medium if the rule that got broken only lives in application code, like a service or controller function, not in a database constraint, ORM annotation, or migration, and it only affects the one record submitted. If the rule is enforced by an ORM level annotation on the model itself, treat that as schema level and call it High instead. Call it Low if the data itself was fine, but the error message was inconsistent between forms or entry points for the same failure.
