# Round 1 data-seeding controls - multi-touch attribution

Clone the warehouse and empty output destinations for `R1-A` through `R1-D`. Each run must start with
the same frozen reporting window, source rows, FX table, and empty Run Log, and use
`[ATTRIBUTION-R1-<run>]` on every writable artifact. Keep per-opportunity timelines, attribution math,
expected CACs, and ticket expectations in an evaluator-only manifest.

Seed unresolved click IDs, Contact-ID fallback, single/two/three-touch paths, cross-platform touches,
no-resolved-touch cases, a missing FX rate, duplicate-ticket behavior, high spend with zero conversions,
and last-click differences just above and below the 20 percent boundary. Include raw PII in one source
field for redaction and a duplicate-Teams-post variant. The test data below is the domain baseline.

Create a complete test environment for a fictional company called Solstice Cloud. This setup is only for testing a weekly multi-touch marketing attribution workflow. Do not connect to any real Google Ads, Meta Ads, LinkedIn Ads, GA4, CRM, or external marketing platforms. All marketing, analytics, and CRM information must exist only as sample data inside Google Sheets.

If a resource already exists with the exact required name, reuse it instead of creating another one.

Currency | Rate to INR | Effective Start | Effective End | Source

Populate the remaining tabs with realistic fictional sample data covering Monday June 29, 2026 through Sunday July 5, 2026 (Asia/Kolkata).
