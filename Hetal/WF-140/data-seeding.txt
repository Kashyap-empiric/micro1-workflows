Create the governance policy with these binding rules:

1. Out of scope: tools with external/client access, or data under a legal/compliance retention obligation tied to the platform. Record as kept; never retire or retain as a target.
2. Standards: Project Management → Jira; internal Communication → Microsoft Teams; File Storage → OneDrive; CRM → HubSpot; Time Tracking → Harvest. Standards are never retired.
3. Identity report is the usage source of truth. “External” means outside SSO and is not evidence of waste.
4. Quotes override tracker costs. Monthly costs × 12. EUR × 1.08 USD.
5. Savings = annual retired-tool cost minus incremental standard-seat cost. Standard spare licences = licences minus identity-report users. A $0 standard has $0 seat price.
6. Create a Jira ticket only for saving ≥ $3,000.
7. Renewal within 21 days, inclusive, is frozen: record and ticket when eligible, but defer action to next cycle.
8. Complementary tools are not overlaps: whiteboarding ≠ UI design; web/marketing analytics ≠ in-product analytics.
9. If policy lacks a sanctioned target or a tracker category is blank, mark unresolved; do not infer a target or saving.

Create a reset procedure that, after results are captured:
1. Deletes only Jira issues carrying that exact run tag from the dedicated test project.
2. Deletes only Teams messages carrying that exact run tag from the dedicated test channel.
3. Deletes only Gmail drafts carrying that exact run tag.
4. Restores the run’s tracker to blank output columns K:O and restores all source cells from its immutable baseline.
5. Verifies zero tagged Jira issues, Teams posts, and Gmail drafts remain.
6. Records reset verification in the control sheet.

Finally, return:
- Links/IDs for each run’s input files
- The exact model prompt for each run, with its run tag
- The reset command or documented reset procedure
- A concise evaluator checklist
