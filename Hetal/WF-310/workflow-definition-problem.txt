Runs a production RAG system's full query log through both BM25 sparse retrieval and dense vector retrieval separately, then analyzes the complementarity of what each finds. Identifies queries where BM25 exclusively retrieved the correct chunks - exact-match product codes, technical error codes, proper nouns, and acronyms that dense vector embeddings failed to weight correctly. Identifies queries where dense vector search exclusively retrieved relevant chunks - paraphrase queries, conceptual questions, and semantic equivalence cases where BM25 found zero matches despite relevant content existing. Calculates the query category distribution in production: what percentage of real user queries are exact-match (BM25 wins), semantic (dense wins), or mixed (hybrid needed). Tests the Reciprocal Rank Fusion weighting to find the optimal α parameter for combining BM25 and dense scores that maximizes Recall@5 for the actual query distribution. Verifies the 39%+ Recall@5 improvement from hybrid over dense-only on the specific document corpus. Exports complementarity analysis to Google Sheets with query category, BM25-only recall, dense-only recall, hybrid recall, and optimal fusion weight per query category.
