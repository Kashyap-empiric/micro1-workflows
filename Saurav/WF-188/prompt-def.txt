For any endpoint that makes two or more billable calls, figure out whether any pair of them is genuinely independent, meaning the second call doesn't need anything the first call produced, versus a pair where one call is built on the previous call's output. Flag the independent case as a real parallelization opportunity (with a rough sense of how much latency it could save), and call out the dependent case explicitly as not one, even though it might look similar from the outside.

Also look for prompt caching opportunities: a call whose static prompt is long and effectively unchanged request after request is a candidate, but whether it's actually worth flagging depends on the provider. Anthropic's Messages API only caches a prompt if the code explicitly turns caching on for it, so a long, reused, uncached Anthropic prompt is a real miss worth flagging with a rough savings estimate. OpenAI and Gemini handle prompt caching automatically once a prompt clears their own length thresholds, no code change needed, so don't treat those the same way, a long repeated prompt there isn't sitting on unclaimed savings the way an uncached Anthropic one is.
