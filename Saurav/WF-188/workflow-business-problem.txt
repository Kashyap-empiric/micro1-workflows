FastAPI LLM Integration Cost & Latency Feature Attribution Monitor

Every FastAPI service with LLM integrations in 2026 has a cost problem nobody has decomposed: which specific API endpoint is burning 70% of the monthly OpenAI bill, which feature's prompt is generating 4× more tokens than necessary, and which endpoint has p95 latency of 18 seconds because it makes 3 sequential LLM calls that could be parallelized. Workflow reads all FastAPI route files from GitHub, identifies every LLM API call (OpenAI, Anthropic, Gemini) with the prompt template used per endpoint, reads Supabase logs for actual request counts and response times per endpoint over the past 7 days, estimates token consumption per endpoint by calculating prompt template length + average response length × request volume, calculates monthly cost attribution per endpoint and per feature using current API pricing fetched via Web Search, detects endpoints making sequential LLM calls where the second call doesn't depend on the first (parallelizable), detects prompts with excessive system prompt repetition that could use caching, generates a weekly LLM cost and latency attribution report in Google Sheets showing cost-per-feature ranked by waste. Codex must trace LLM API patterns through route code, combine cost math with usage data, and identify parallelization opportunities in async call chains.
